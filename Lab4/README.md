# Практическая работа №4

В ходе лабораторной работы был сгенерирован массив случайных чисел на GPU размером до 1,000,000 элементов, затем реализована параллельная редукция суммы элементов с использованием только глобальной памяти и с комбинацией глобальной и разделяемой памяти, измерено время выполнения и показано ускорение при использовании shared memory; далее массив был разбит на небольшие подмассивы, которые сортировались пузырьком в локальной памяти потоков, после чего выполнялось слияние отсортированных подмассивов с использованием разделяемой памяти; для всех операций проведены замеры времени для разных размеров массивов и построены графики зависимости производительности от объема данных.
# Контрольные вопросы - ответы
**1. Чем отличаются типы памяти в CUDA и в каких случаях их использовать?**

- Глобальная память: доступна всем потокам, но медленная; используется для хранения больших данных.

- Разделяемая память (shared memory): быстрая, общая для потоков блока; используется для обмена данными между потоками блока.

- Локальная память: хранится в регистрах потока, быстрая, но ограниченная; используется для временных переменных внутри потока.

**2. Как использование разделяемой памяти влияет на производительность?**

Снижает количество обращений к медленной глобальной памяти, ускоряет вычисления внутри блока.

**3. Доступ и как его обеспечить?**

- Глобальная память доступна всем потокам.

- Shared memory доступна всем потокам блока.

- Локальная память доступна только одному потоку (через регистры).

**4. Какие сложности возникают при работе с большим объемом данных на GPU?**

- Ограничение по памяти.

- Потенциальные конфликты при одновременном доступе потоков к глобальной памяти (решается атомарными операциями).

- Балансировка нагрузки между блоками.

**5. Почему важно минимизировать доступ к глобальной памяти?**

Глобальная память медленная, поэтому частые обращения замедляют выполнение программы.

**6. Как использовать профилирование для анализа производительности CUDA-программ?**

Использовать инструменты вроде **Nsight Compute** или **nvprof**, чтобы измерять время выполнения ядра, загрузку памяти, пропускную способность. Определять узкие места и оптимизировать использование памяти.
