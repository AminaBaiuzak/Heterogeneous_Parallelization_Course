# Практическая работа №5

В ходе практической работы была реализована параллельная структура данных стек и очередь с использованием технологии CUDA и атомарных операций для обеспечения корректного доступа нескольких потоков к общим данным. Для обеих структур были реализованы операции push/pop и enqueue/dequeue, а также проведены замеры времени выполнения на GPU и CPU. Экспериментальные результаты показали, что очередь на GPU демонстрирует наименьшее время выполнения благодаря более простому шаблону доступа к памяти, тогда как стек имеет больший накладной расход из-за частых атомарных операций. Сравнение с последовательными реализациями на CPU показало, что параллельная реализация на GPU обеспечивает преимущество для очереди, в то время как для стека выигрыш по времени менее выражен из-за высокой стоимости синхронизации.

# Контрольные вопросы - ответы

**1. В чём отличие стека и очереди?**

**Стек** работает по принципу _LIFO_ (последний вошёл — первый вышел): операции добавления и удаления выполняются с одного конца.

**Очередь** работает по принципу _FIFO_ (первый вошёл — первый вышел): добавление происходит в конец, а удаление - из начала.

**2. Какие проблемы возникают при параллельном доступе к данным?**

При параллельном доступе возможны:

- состояния гонки (race conditions);

- потеря или перезапись данных;

- некорректный порядок операций;

- конфликты при записи в одну область памяти.

**3. Как атомарные операции помогают избежать конфликтов в параллельных структурах данных?**

Атомарные операции обеспечивают неделимость операций чтения и записи, гарантируя, что изменение данных выполняется только одним потоком за раз. Это предотвращает состояния гонки при обновлении общих счётчиков и индексов (например, top, head, tail).

**4. Какие типы памяти CUDA используются для хранения данных?**

В CUDA используются:

1. глобальная память - доступна всем потокам, но медленная;

2. разделяемая память - быстрая, общая для потоков одного блока;

3. локальная память (регистры) - доступна одному потоку, очень быстрая;

4. константная и текстурная память - используются для специальных задач.

**5. Как синхронизация потоков влияет на производительность?**

Синхронизация обеспечивает корректность вычислений, но увеличивает накладные расходы. Частое использование синхронизации и атомарных операций может снижать производительность из-за ожидания потоков и сериализации выполнения.

**6. Почему разделяемая память важна для оптимизации работы параллельных структур данных?**

Разделяемая память значительно быстрее глобальной и позволяет потокам одного блока эффективно обмениваться данными. Это уменьшает количество обращений к глобальной памяти и снижает задержки, что особенно важно при реализации параллельных структур данных.
