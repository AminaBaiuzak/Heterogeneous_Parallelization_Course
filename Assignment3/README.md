# Assignment 3: Архитектура GPU и оптимизация CUDA-программ

**Задание 1 — Поэлементное умножение массива (Global vs Shared Memory)**
```cmd
Global Memory: 49.155 мс
Shared Memory: 0.070855 мс
```
Вывод: использование разделяемой памяти ускоряет работу почти в 700 раз, так как доступ к shared memory значительно быстрее, чем к глобальной памяти GPU.

**Задание 2 — Поэлементное сложение двух массивов, влияние размера блока**
```cmd
Block Size 128: 7.41383 мс
Block Size 256: 0.006103 мс
Block Size 512: 0.002243 мс
```
Вывод: увеличение числа потоков в блоке до оптимального значения существенно ускоряет выполнение ядра. Очень маленькие блоки не используют возможности GPU полностью.

**Задание 3 — Коалесцированный vs некоалесцированный доступ к памяти**
```cmd
Коалесцированный доступ: 0.0002 мс, 37764.35 GB/s
Некоалесцированный доступ: 0.0003 мс, 27412.28 GB/s
Ускорение: 1.38x
```
Вывод: правильный (коалесцированный) шаблон доступа потоков к глобальной памяти повышает пропускную способность и уменьшает задержки, хотя на современных GPU эффект может быть менее заметен на небольших массивах.

**Задание 4 — Оптимизация конфигурации сетки и блоков**
```cmd
threadsPerBlock = 64 → 0.0061 мс
threadsPerBlock = 128 → 0.0021 мс (оптимальный)
threadsPerBlock = 256 → 0.0026 мс
Speedup: 2.84x
```
Вывод: выбор оптимального количества потоков в блоке критически влияет на производительность. Слишком маленькие блоки не полностью загружают GPU, слишком большие могут вызвать накладные расходы на синхронизацию и ограничить occupancy.

# Контрольные вопросы - ответы к Assignment 3
**1.	Какие основные типы памяти существуют в архитектуре CUDA и чем они отличаются по скорости доступа?**

a.	Регистры (Registers): самая быстрая память, локальна для каждого потока, недоступна другим потокам.
b.	Shared Memory (Разделяемая память): очень быстрая, доступна всем потокам блока, синхронизация через __syncthreads().
c.	Global Memory (Глобальная память): большая, но медленная (200–400 тактов), доступна всем потокам.
d.	Local Memory: выделяется для потоков, но фактически хранится в глобальной памяти → медленно.
e.	Constant Memory: доступ к одной константе быстрый при одинаковых обращениях потоков.

**2.	В каких случаях использование разделяемой памяти позволяет ускорить выполнение CUDA-программы?**

a.	Когда несколько потоков блока обращаются к одним и тем же данным несколько раз.
b.	Когда нужно уменьшить число медленных обращений к глобальной памяти.
Пример: умножение массива с загрузкой данных в shared memory (Задание 1).

**3.	Как шаблон доступа к глобальной памяти влияет на производительность GPU-программы?**

a.	Коалесцированный доступ: последовательные потоки читают последовательные адреса → минимальное количество транзакций → высокая пропускная способность.
b.	Некоалесцированный доступ: случайные или разреженные адреса → много транзакций → низкая производительность.
(Задание 3 показало ускорение 1.38x при коалесцированном доступе).

**4.	Почему одинаковый алгоритм на GPU может показывать разное время выполнения при разных способах обращения к памяти?**

Из-за разной организации памяти: доступ к глобальной памяти медленный, shared — быстрый. Разный шаблон доступа (коалесцированный vs некоалесцированный) меняет число транзакций памяти. Размер блоков и occupancy GPU тоже влияет на производительность.

**5.	Как размер блока потоков влияет на производительность CUDA-ядра?**

a.	Слишком маленькие блоки → GPU недогружен → низкая производительность.
b.	Слишком большие блоки → уменьшение числа блоков на мультипроцессоре, возможные накладные расходы.
c.	Оптимальный блок обычно кратен warp size (32 потока) и обеспечивает высокую occupancy (Задание 2 и 4).

**6.	Что такое warp и почему важно учитывать его при разработке CUDA-программ?**

Warp — группа из 32 потоков, выполняющихся одновременно на CUDA SM (Streaming Multiprocessor). Если потоки warp выполняют разные ветви условий, появляется warp divergence → снижается производительность. Для максимальной скорости нужно, чтобы все потоки warp выполняли один и тот же шаблон памяти и вычислений.

**7.	Какие факторы необходимо учитывать при выборе конфигурации сетки и блоков потоков?**

a.	Размер блока (threadsPerBlock) → кратность warp size
b.	Количество блоков (gridDim) → чтобы покрыть все элементы массива
c.	Ограничения GPU: shared memory на блок, регистры
d.	Шаблон доступа к памяти (coalesced / non-coalesced)
e.	Задачи синхронизации внутри блока

**8.	Почему оптимизация CUDA-программы часто начинается с анализа работы с памятью, а не с изменения алгоритма?**

Потому что доступ к памяти обычно главный узкий горлышко на GPU. Даже быстрый kernel с плохим доступом к глобальной памяти будет медленным. Использование shared memory и коалесцированных шаблонов доступа дает значительный прирост производительности, иногда в десятки или сотни раз.
