Задание 1 (Среднее и стандартное отклонение)
--------------------------------------------------

При увеличении числа процессов с 2 до 4 время выполнения увеличилось, что связано с небольшим размером данных и накладными расходами на коммуникацию. Ускорение (Speedup) меньше идеального, а эффективность падает, что показывает влияние накладных расходов и синхронизации на малых объёмах данных.
Для больших массивов данных увеличение числа процессов дало бы реальное ускорение.

Задание 2 (Метод Гаусса)
--------------------------------------------------

Время выполнения крайне мало (миллисекунды), поэтому при 4 процессах решение стало даже медленнее, чем при 2 процессах.
Это связано с тем, что накладные расходы на распределение данных и синхронизацию превышают время вычислений.
Эффективность параллельной обработки мала — на малых системах линейных уравнений параллелизация неэффективна.

Задание 3 (Алгоритм Флойда-Уоршелла)
--------------------------------------------------

Для графа из 5 вершин параллельное выполнение также показало меньшую эффективность при 4 процессах, так как объем данных слишком мал для оправдания коммуникационных расходов.
Speedup ниже идеального, эффективность падает. Для больших графов эффект параллельного ускорения был бы заметен.

--------------------------------------------------

При малых объемах данных увеличение числа процессов не всегда ускоряет вычисления.
Накладные расходы на передачу данных, синхронизацию и барьеры могут превысить выигрыш от параллельных вычислений.
Эффективность параллельной программы зависит от баланса нагрузки, объёма данных и числа процессов.
Для больших массивов данных и задач с интенсивными вычислениями увеличение числа процессов улучшает производительность.
Рекомендуется оптимально подбирать количество процессов под размер задачи и использовать техники минимизации коммуникаций (сбор сообщений, неблокирующие операции, перекрытие вычислений и передачи данных).

# Контрольные вопросы - ответы

**1. Как изменяется время выполнения программы при увеличении количества
процессов? Почему?**

**Общее правило:**

- При увеличении числа процессов время выполнения обычно уменьшается, так как вычисления делятся на большее количество процессов.

- Например, для задачи 1 (среднее и СКО) 1 000 000 элементов делится на большее число процессов -> меньше данных на процесс -> быстрее вычисление локальных сумм.

**Но есть нюансы:**

- Существуют накладные расходы на коммуникацию (рассылка и сбор данных через MPI_Scatterv, MPI_Reduce, MPI_Gatherv).

- Для малых задач увеличение процессов может даже увеличить время, потому что процессы тратят больше времени на обмен данными, чем на вычисления.

**Пример по выводу:**

- Задание 1: ```2 процесса → 0.042 с```, ```4 процесса → 0.118 с```, для маленькой нагрузки накладные расходы растут.
Для больших массивов 4 процесса будут быстрее, чем 2, так как вычисления распределяются.

**2. Какие факторы могут влиять на производительность программы?**

- Накладные расходы на коммуникацию между процессами.

- Баланс нагрузки: если данные распределены неравномерно, один процесс может ждать других.

- Синхронизация процессов (```MPI_Barrier, MPI_Bcast```) — процессы ждут друг друга.

- Размер данных: большие массивы требуют больше памяти и времени на передачу.

- Скорость сети или пропускная способность (для кластеров).

**3. Как можно оптимизировать передачу данных между процессами?**

- Минимизировать количество сообщений: объединять маленькие передачи в большие.

- Использовать неблокирующие операции (```MPI_Isend, MPI_Irecv```) для перекрытия вычислений и передачи данных.

- Передавать только необходимые данные, а не весь массив.

- Использовать ```Scatterv/Gatherv``` с продуманными смещениями и размерами частей.

- Стараться уменьшать частоту синхронизаций (```MPI_Barrier```), если они не нужны.

**4. Какие ограничения возникают при работе с большими данными?**

- Ограничения памяти на каждом процессе — процесс не может держать слишком большой кусок данных.

- Пропускная способность сети — при передаче больших массивов может возникнуть узкое место.

- Время коммуникаций может превысить время вычислений -> эффективность падает.

- Необходимость эффективного разбиения данных — чтобы все процессы были загружены равномерно.

- Сложность синхронизации — чем больше данных, тем тяжелее поддерживать согласованность.
